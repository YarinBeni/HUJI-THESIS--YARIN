1. **The success criterion is too weak, and it conflicts with the repo’s own bias-check conclusion.**  
`PLAN.md` treats beating the unigram baseline as evidence the LLM may add something beyond character statistics, but the project’s bias analysis on the same letters corpus already shows near-perfect classification from surface transliteration features alone. On this dataset, `>84.8%` is not a meaningful bar for “deeper representation.”

4. **You identify tokenization/length confounds in Step 0, but the later pipeline does not actually control for them.**  
The plan explicitly worries that periods may differ in token counts or tokenization behavior, but Step 1 mean-pools all token positions and Step 2 never includes token-count, text-length, or cleaned-vs-raw ablations. That leaves a major confound unaddressed.

```36:48:v_1/src/linear_probing/PLAN.md

- Print raw text → tokenized tokens → decoded tokens
- Count: tokens per text, unknown/fallback tokens, average token length
- Check: do different periods produce systematically different token counts or patterns?

**What we're looking for:**
- If Akkadian is tokenized into single-character or byte-level pieces → the model treats it as raw bytes, probing may still work but the "representation" is shallow
- If some Akkadian words survive as recognizable subwords → the model has partial knowledge
- If token counts differ wildly by period → another surface feature the probe could exploit (like text length in the bias check)
```

## Bottom Line

My view: the plan is promising operationally, but not yet convincing scientifically. The biggest fix is to redefine success around **controlled comparisons**, not raw accuracy.

I’d revise it before implementation in three ways:
1. Use the **same splits/protocol** for probe and TF-IDF baselines.
2. Add **control probes/ablations**: token count, text length, cleaned corpus, names/provenance masking, random-label sanity check.
3. Tone down Outcome A/B claims so a mid-layer peak is treated as **suggestive**, not decisive.
