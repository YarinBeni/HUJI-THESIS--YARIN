## Context (research plan + emails)

**Research plan** (`yarin/research_plan.md`): Pre-Track A was framed as a **bias gate** — you wanted period classification to stay near **chance (~33%)** so the test set would not be trivially separable. Tracks A–C then build LLM evaluation, linear/PLS “time direction,” and SAE interpretability.

**Emails** show the empirical result went the other way: **simple models get very high accuracy** on the letters (e.g. unigrams 84.8%, 69.1% after heavy cleaning; bigrams/n-grams much higher). Domain experts disagree on how alarming that is (Nathan: corpora *should* differ; Barak: that weakens the “LLM adds insight” story if lexicon dominates). The thread **converges on a pivot**: de-emphasize letters as the main benchmark, add **~20 hand-picked texts** for sanity checks, **EDA on SEAL** (literary, harder), and still pursue **LLM internal structure** (e.g. linear probing).

So the **high-level story** has shifted from “validate an unbiased letters benchmark” to “letters are an easy lexical task; harder evaluation moves to SEAL / expert-chosen cases; probing still tells us how models represent period in embeddings.”

## Review of `v_1/src/linear_probing/PLAN.md`

**What works well**

- **Step 0 (tokenization sanity)** is the right first move for extreme-OOD script: you separate “byte soup” from structured subwords and catch period-linked length/tokenization artifacts before you trust any probe.
- **Layer-wise probes + curves** match Gurnee & Tegmark and your Track B framing; comparing early vs mid vs late peaks is the right qualitative readout.
- **Storage math, mean pooling, ridge/5-fold CV** are concrete and implementable; optional last-token pooling is a good hedge for causal LMs.
- **Three outcomes (A/B/C)** give a clear decision tree toward SAE, “surface-only” write-up, or fine-tuning — consistent with the main research plan’s fallbacks.
- **Pointing at the same parquet + tier0 cleaning** keeps the pipeline comparable to the bias check.

**Gaps / things to tighten (given the email pivot)**

1. **Narrative vs letters** — The plan still centers **4,957 letters** as the primary corpus. That matches “we still run probing,” but you may want one explicit sentence that **letters are now a controlled lab setting** (or “Phase 1 probing”), while **SEAL / Nathan’s 20 texts** are the harder, thesis-facing evaluation when data lands. Otherwise a reader could think you’re contradicting “drop letters as the test.”

2. **Baselines are a stiff bar** — Comparing to **99.2% / 96.7%** n-gram baselines sets an almost impossible ceiling for any probe on the same labels. Failure to match that does **not** imply “LLM is useless”; it often means **the task is nearly solved by lexicon**. I’d treat unigram / “maximally cleaned” baselines as the main fairness checks, and treat n-gram peaks as “lexical oracle” context in the write-up, not a bar the probe must clear to count as success.

3. **Outcome A threshold (`>85%`)** — That is barely above **84.8%** unigrams; noise from CV can flip the story. Consider pairing accuracy with **macro-F1**, **permutation / significance**, or explicit comparison to **69.1%** (max cleaned) to show the probe is not just riding the same trivial cues you tried to strip.

4. **Leakage / dual use of the same texts** — You train the probe on the same distribution you already showed is lexically separable. The probe may recover **lexical period markers** that an LLM never “understood” in a linguistic sense. Outcome B already gestures at correlating probe weights with TF-IDF; I’d elevate that: **weight-level or CKA-style alignment** with bag-of-n-grams is central to the “is this just TF-IDF in a big space?” question.

5. **Mean pooling** — Fine for a first pass; if some texts are much longer in tokens, **masked mean** vs **[CLS]-like last token** can differ. You already note last-token as secondary — worth actually running if early-layer peaks look like length artifacts.

6. **Track B wording in the main plan** — The main plan stresses **PLS** as the supervised geometry tool; `PLAN.md` puts PLS in “additional analysis” under Step 2. That’s fine for implementation order, but you might want **one primary supervised direction** (PLS or ridge direction) named as the object you’ll eventually feed to SAEs so Track B and C stay aligned.

---

**Bottom line:** The implementation plan is **technically sound and well staged** (tokenize → extract → probe → interpret). The main intellectual update from the emails is **not** “stop probing,” but **reframe what beating which baseline means** and **tie letters-based probing to the harder SEAL / expert tests** so the thesis story stays coherent. If you want, we can edit `PLAN.md` in-repo to add a short “Relationship to letters vs SEAL” subsection and soften the n-gram baseline language in one pass.
