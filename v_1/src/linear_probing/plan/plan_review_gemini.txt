### Review of `v_1/src/linear_probing/PLAN.md`

Your `PLAN.md` is well-structured and methodologically sound, but **it is currently out of sync with the conclusions reached in your email thread.**

Here are my thoughts and suggested changes for the plan:

**1. The Dataset Focus is Outdated (Crucial)**
*   **Current Plan:** Steps 1 and 2 are built entirely around running the 4,957 letters through the LLM to extract activations and probe them. 
*   **The Problem:** You agreed in the emails to "drop the letters data test" because the 99% n-gram baseline makes the results uninteresting. If you run the linear probe on the letters and get 99% accuracy, you won't know if the LLM has deep temporal understanding or if it just acts as an expensive n-gram detector.
*   **Recommendation:** Update the plan so that the **SEAL literary texts** are the primary target for Step 1 and Step 2. If you still want to run the letters data, it should be explicitly framed as a "pipeline test" on a small subset (e.g., 100 texts) just to ensure the code works before the SEAL data arrives, not as the main experiment.

**2. Missing the EDA Step**
*   **Current Plan:** Jumps straight into tokenization checks, layer-by-layer activation extraction, and ridge regression.
*   **The Problem:** Your email explicitly outlines doing "EDA on SEAL Data" first (TF-IDF, LLM embeddings, dimensionality reduction like PCA/UMAP) before deep linear probing. 
*   **Recommendation:** Insert a "Step 0.5: EDA on Final Embeddings" where you extract just the final layer embeddings of the SEAL texts and run UMAP/PCA to see if there is any natural clustering before spending hours extracting all 32 layers.

**3. Baselines Need to be Updated for SEAL**
*   **Current Plan:** Lists the 84.8% / 99.2% letters baselines.
*   **Recommendation:** Note in the plan that new TF-IDF baselines must be established specifically for the SEAL data once it arrives. The letters baseline is irrelevant if you run the probe on SEAL texts.

**4. Step 0 (Tokenization Check) is Excellent**
*   This is a fantastic step. Because Akkadian is highly Out-Of-Distribution (OOD), Llama-3/Gemma might just tokenize everything into raw bytes. If the text is shredded into individual characters, your "mean pooling" in Step 1 might dilute the signal. Keep this step exactly as is.

### Summary
Your code architecture for the linear probe (Steps 0-3) is perfect, but you are aiming the "cannon" at the wrong dataset. I suggest rewriting the **Data**, **Baseline**, and **Step 1** sections of `PLAN.md` to center around the upcoming SEAL dataset, keeping the letters data only as a fast, optional debugging tool for your Python scripts.
