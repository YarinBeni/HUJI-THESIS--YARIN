# Chunrong Data Cleaning Decisions

**Date**: March 8, 2026
**Context**: Documenting all data cleaning and normalization decisions made with Chunrong Ni (data preparation lead) across the email correspondence rounds (January–March 2026).
**Purpose**: Record what was changed, why, and what was decided — for paper justification and pipeline reproducibility.

---

## Background

The three evaluation corpus CSV files were prepared and normalized by Chunrong Ni from original source editions. They went through multiple rounds of cleaning based on discussion between Chunrong (Assyriologist) and Yarin (ML/CS). This document tracks all changes and the decisions behind them.

**Files affected:**
- `archibab_nor.csv` — Old Babylonian letters (Group 1, ~1800 BCE)
- `oracc_let_adm_nor.csv` — Neo-Assyrian letters (Group 2, 9–7 cent. BCE)
- `lbl_nor.csv` — Late Babylonian letters (Group 3, ~600 BCE)

## Round 1 — Initial Data Delivery (January 20–23, 2026)

Chunrong delivered the first version of all three normalized CSV files.

**Known issues flagged at delivery:**
- LBL (`lbl_nor.csv`): Lemmas generated by an AI lemmatizer — Chunrong warned "must be some mistakes"
- LBL: Working from a Word document (not a stable critical edition) — transliteration may have errors; Chunrong said he would correct them

**Normalization convention confirmed (email, Jan 2026):**
- All signs connected using `"-"` (hyphen), regardless of whether they are superscripts, numbers, or punctuation
- Subscript numbers normalized to plain ASCII: `lu₂` → `lu2`, `lu₃` → `lu3`, etc.
- This convention applies uniformly across all three corpora

## Round 3 — Final Pre-Baseline Cleaning (March 8, 2026)

Chunrong proactively reviewed ARCHIBAB transliterations and identified a further issue, which led to a final round of cleaning before running the LLM baseline.

### Broken Words Decision (ARCHIBAB + ORACC)

**Issue**: Some partially restored words appear in the source data with only the visible portion preserved. Example: `[ba-ri]-i` → stored as just `i` (the bracketed/restored part dropped, only the surface reading kept).

**Decision**: Follow the **EvaCun paper standard** — keep the visible portion of partially restored words as-is, without the restoration brackets. Do not attempt to restore or complete them.

**Rationale**: This is the convention used in the EvaCun paper that the Archibab data originates from. Consistency with the source standard is the most defensible choice for a paper.

**Applied to**: ARCHIBAB and ORACC (same standard across both).

### Sign Normalization (ARCHIBAB + ORACC)

Minor sign-level normalization fixes applied:
- `U4` → `UD`
- `UNU` → `UNUG`

These are variant sign spellings that were standardized to the canonical form. Changes were described by Chunrong as "only few minor changes."

### LBL — Problematic Letters Deleted

**Decision**: Letters with "bad" transliteration in LBL were deleted entirely (whole texts, not individual words).

**Rationale**: The LBL source edition has known quality problems. Rather than include unreliable transliterations that could confuse the LLM baseline, Chunrong removed the problematic texts. A corrected edition is forthcoming.

**Impact**: LBL text count will decrease further from the Round 2 count. Exact number of deleted texts to be verified after rebuilding evaluation corpus.

## Summary of All Decisions

| Decision | What | Why |
|----------|------|-----|
| Aramaic removal | Removed non-Akkadian entries from ORACC | Corpus must be Akkadian-only |
| Broken word removal | Removed `a-x-x-x-x` style tokens from ORACC and LBL | Uninformative; no recoverable reading |
| Partially restored words | Keep visible portion only (follow EvaCun standard) | Consistency with source paper convention |
| Sign normalization | `U4→UD`, `UNU→UNUG` | Standardize to canonical sign forms |
| LBL bad letters | Delete entire texts with unreliable transliteration | Better to exclude than include noisy data |
| Homonyms | Follow Archibab paper principle initially | Sufficient samples per word more important at this stage |
| Genre | Letters only across all 3 groups | Control for genre bias in temporal classification |

### What Are the "man" (Manually Checked) Files?

Chungrong confirmed: **"Manually checked files are used for evaluation of the normalization tools."** These are QA files — a subset of 111 texts (22 + 62 + 27) that Chungrong manually verified to validate the automated normalization. They are **strict subsets** of the corresponding main files (all fragment_ids in "man" files exist in the main files).

The corrections found in the "man" files include:
- **MEŠ → meš** case normalization (dominant pattern)
- **Domain reclassification** in ORACC (NAAdm ↔ NALet fixes for some texts)
- **Transliteration corrections** (e.g., `KUG-UD` → `KU3-BABBAR`, `EN-LIL2-ki` → `NIBRU-ki`)

### Decision: Use Main Files As-Is

**Chungrong's guidance**: "They are not so different. You can use either the main files or merged result."

**Decision**: Use the main files directly, without merging corrections from the "man" files. Rationale:
1. Chungrong confirmed MEŠ → meš normalization is already applied corpus-wide in the main files (verified: only 1 stray `MEŠ` in 229K ORACC rows)
2. The differences are minor and Chungrong said the results would be similar
3. Minimizes preprocessing complexity before baseline run

### MEŠ Normalization — Confirmed Applied

Chungrong confirmed: "MEŠ → meš is also applied to all texts in the corpus. (because in different systems, MEŠ or meš are used. I made them all meš)."

Verified programmatically — the new main files contain essentially no uppercase `MEŠ`.

### ORACC Domain Overlap — NAAdm/NALet Duplicates

Chungrong explained: "Some administrative texts (not always) are also letters. These two corpus contain many repeated texts. So many texts appear twice. E.g., P224378, NALet + P224378, NAAdm."

**Decision**: "For the main files, do not use texts with NAAdm." This is already handled by the pipeline — `01_create_corpus.py` filters to `NALet` only.

### Only Transliteration Used — Confirmed

Chungrong asked: "Only the transliteration is used, right?"

**Answer**: Yes. The pipeline (`02_prepare_texts.py`) reconstructs texts using only the `clean_value` column. The `lemma`, `value`, and other columns are not used in the LLM baseline evaluation.

### Green Light

Chungrong confirmed: "I think you can run the baseline evaluation."
